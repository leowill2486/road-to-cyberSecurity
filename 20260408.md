Summary of Today's Learning: Web Security Foundations

1. The Essence of Injection

Concept: Injection occurs when an application fails to distinguish between "data" (user input) and "commands" (code logic).

Mechanism: When you use functions like .innerHTML, the browser "interprets" your text as active HTML/JavaScript code rather than just displaying it.

2. Attack Surface

You learned that security is not just about the input box. The "Attack Surface" includes:

Frontend Code: Vulnerable DOM properties (like innerHTML).

APIs: Intercepting and modifying requests between the client and server.

Browsers & Plugins: Malicious extensions or client-side script execution.

Supply Chain: Vulnerabilities hidden within third-party libraries (NPM packages, UI components).

3. Modern Frameworks vs. Security 

Auto-Escaping: Frameworks like React, Vue, and Angular provide built-in protection by treating data as plain text by default.

The "Escape Hatch": Vulnerabilities usually arise when developers bypass security features using "dangerous" functions (e.g., dangerouslySetInnerHTML in React or v-html in Vue).

4. Defensive Mindset

Zero Trust: Never trust user input. Everything coming from the outside must be Sanitized (cleaned) or Escaped (neutralized).

Defense in Depth: Security should be implemented at every layer—frontend, API gateway, and backend database.
